# One system, four ways

A student describes a small spatial system through parts, steps, a repeatable procedure and parameter dependencies, then inspects the same calculation in a picture, table and source.

## Guided first encounter

[Start with a number](start.html) before using the four open instruments. Six individually addressable steps connect context, representation, relationships, a geometric rule, actual bounded code execution and a small shared-identity system. These are related teaching cases, not one unchanged physical object: an initially unspecified panel, six square facade panels, a row of rectangular panels and two overlapping groups.

The entry is English by default and fully switches to Serbian. Both Design routes share the site’s JSON language preference at `or-studio-v1:lang`. The notebook uses `or-studio-v1:learning`; browser storage is optional and may be unavailable or evicted. No answers are preselected. Predictions and explanations are local notes, not automated marks. Print exports the currently visible step to the browser’s print dialog; only revealed explanations are included.

`learning-model.js` supplies the calculations and a five-statement interpreter. The supported syntax is `let n = integer;`, `let w = integer;`, `let gap = integer;`, followed by assignments to `joints` and `span` using prior names, numeric literals, `+`, binary `-`, `*` and parentheses. This is a deliberately bounded subset, not a general JavaScript engine. Counts and lengths are checked separately. No `eval`, calls, member access, loops, strings, remote execution or dependencies are used. Run executes the supported program; subsequent controls inspect its recorded states. A successful execution can still fail the independent geometric check.

Inputs: integer count 1–6, width 200–1200 mm and gap 0–100 mm. The row has 1200 mm-high panels and only interior gaps. The shared-panel example chooses a 1200 or 1500 mm height. Facade cells are squares; the row diagram is explicitly schematic and not to vertical scale.

JSON schema `computing-studio-learning/v1` stores a version, save time, language, step, inputs, predictions, notes, reveals and editable code. Files are limited to 32 KiB; required keys, types, ranges and text lengths are validated before a replacement is offered. A valid import requires an explicit Apply action; an invalid import cannot replace current work. Calculated answers and traces are not accepted from files. Unfinished code can be preserved as plain text, but import never executes it. Run is required again after reopening. Local downloads and imports do not submit work, verify identity or establish attendance.

From the public package root: `node tests/learning.test.cjs`. The supplied checks cover known numerical results, spatial permutation invariance, shared IDs, actual interpreter traces, wrong-but-executable rules, input/grammar/unit limits, schema rejection, Unicode round trips and preserved work. Run status and browser evidence are recorded separately by release QA; the presence of tests does not establish that a specific build passed them. Physical phones, screen readers and teaching outcomes need their own checks.

Files for this route: `start.html`, `start.css`, `start.js`, `learning-model.js`. The existing four-mode `model.js` and its numerical contract are unchanged.

Open `index.html` locally or through `lab/dizajn/` in the OR site. English is the default; Serbian uses identical calculations. No build, dependencies, CDN, backend, account, arbitrary-code evaluation or automatic animation. The diagram is supplementary to DOM quantities and tables. The four approaches overlap: a modular arrangement can be parameterised and generated by an algorithm. These examples emphasise different decisions, not four mutually exclusive categories.

## Models and limits

- **Modular:** rectangular panels plus interior joints. Overall width is `cols * panelW_mm + (cols - 1) * joint_mm`; depth is analogous. There is no exterior joint. The default 4 × 3 panels of 600 × 600 mm, with 20 mm joints, gives 12 panels, 2460 × 1840 mm envelope, 4.32 m² panel area and 0.2064 m² joint footprint. The latter is an uncovered geometric area, not a sealant quantity or construction specification.
- **Algorithmic:** start at zero, advance by a chosen step, and optionally add the endpoint at L. At L = 6 m and step = 1.6 m, regular stations are 0, 1.6, 3.2, 4.8 m. The enabled endpoint option adds 6 m, with a final 1.2 m interval. No search for an optimum occurs. Near-integer quotients are snapped within `8 * Number.EPSILON * max(1, abs(L/s))` before flooring. The same accepted quotient decision sets the last coordinate exactly to L and the remainder to zero. `tolerance_m` is the quotient tolerance multiplied by the step, reported as metadata; it is not a competing second snap test. This handles cases such as 1.2/0.4 without duplicating or losing the endpoint; larger genuine residuals remain visible.
- **Procedural:** a row-major grid uses the explicit 32-bit recurrence `state = (1664525 * state + 1013904223) mod 2^32`, implemented with `Math.imul` and unsigned conversion. Each normalised state is compared with a threshold to choose an open or closed cell. The realised opening ratio need not equal the threshold. Reproduction requires the same model version, parameters, seed, generator and iteration order. This is neither cryptographic randomness nor a daylight, thermal, acoustic or structural predictor.
- **Parametric:** a rectangle and its grid form a dependency chain. The default 6 × 4 m envelope, 3 × 2 bays and 80 mm uniform sheet gives 2 × 2 m grid spacings, 24 m² plan area, 1.92 m³ nominal solid volume and 12 grid intersections. Intersections are coordinates, not verified supports. No loads, member sizes, deflection, connection design, material response, openings or waste are calculated.

All numbers are ordinary JavaScript floating point. API validation rejects missing/nonfinite values, fractional discrete counts, invalid booleans and out-of-range inputs. The bounded domains are visible beside the controls: 1–10 columns, 1–8 rows; panel sizes 100–3000 mm; joints 0–150 mm; line 1–20 m and step 0.25–5 m; integer seed 0–4294967295 and threshold 0–1; envelope 1–24 by 1–20 m; grid bays 1–10 by 1–8; thickness 10–500 mm.

## Inspect and keep a record

The selected trace row highlights its corresponding part, station, cell or grid point. Next/First inspect already computed rows; they do not emulate a debugger. Changing an input recalculates the complete model. The displayed code is `Function.toString()` of the actual calculation kernel; public input validation runs before that kernel.

JSON export is a user-triggered local Blob download. It contains `schema: or-design/v1`, `modelVersion`, mode, exact parameter values, units and calculated results. Keep it alongside an explanation or a future portfolio repository; the app does not connect to GitHub. The record does not establish authorship, identity, submission status or engineering validity. No user data is uploaded.

## API and files

`require('./model.js')` or `window.DesignModel` exposes:

- `modular({cols,rows,panelW_mm,panelD_mm,joint_mm})`
- `stations({length_m,step_m,includeEnd})`
- `procedural({cols,rows,seed,openFraction})`
- `parametric({width_m,depth_m,baysX,baysY,thickness_mm})`
- `run(mode, parameters)`, `codeSource(mode)`, `snapshot(mode, parameters)`, `version`

Mode IDs are `modular`, `algorithmic`, `procedural`, `parametric`, also used as URL fragments. Outputs and units are explicit in the returned field names. Models leave inputs unchanged.

From the public repository root run `node tests/dizajn.test.cjs`. Its 26 checks include independently known dimensions/units, area and volume scaling, station coverage and roundoff regressions, BigInt verification of the 32-bit recurrence, seed reproduction, threshold monotonicity, grid invariants, input rejection and record reproduction. Joint area is computed directly as non-overlapping strips and their intersections, avoiding cancellation when decimal panels have zero or very small joints. Browser evidence is maintained outside this portable package; pure tests alone do not establish rendered usability, accessibility certification or learning outcomes.

## Design and honest verdict

The supplied concept is one system with four ways of describing it. The invariant is a plan, numerical evidence and an exposed rule; the variable is which relationship the student chooses to control. A restrained paper/ink/cobalt instrument and the selected-row outline carry the mechanism. Generic cards, fake optimisation, material presets, animation and decorative effects were omitted. The picture precedes the controls on a phone; trace and source follow. There is no motion to disable. Native controls, 44 px buttons/fields, reflow and text/table fallback are implemented; rendered checks remain separate evidence. No physical phone, screen reader, classroom learning trial or 400-user backend benchmark is claimed.

Original teaching code; not a formal syllabus, assignment schedule or professional design tool. Architecture and civil prompts are optional questions. The shared OR course catalogue supplies broader conceptual references.
