# Giza, from a rule

**A rule builds our model; evidence tells us which parts belong to history.**

A local Canvas/DOM instrument for the OR idea collection. English is the default; Serbian Latin is available alongside it. There is no dependency, CDN, analytics, account, persistence or external request during normal use. The six primary-source links require internet access.

## What works

- Choose an integer N from 4 to 10. A change starts a new empty model.
- Add one **complete** layer, play at one layer per second, pause or reset. Nothing autoplays. Playback stops on completion, parameter change, reset, hidden document or page exit.
- Inspect the actual unit cubes, exact table and separate height/cube progress. The newest completed layer is blue; text also identifies completed and waiting layers.
- Read the exact `layersFor` function used by the model. The remaining projection/rendering code is separate.
- Follow four research narratives into six source disclosures with read scopes and limitations. These are research narratives, not additional transport or workforce simulations.

For layer k counted from zero: `side=2*(N-k)-1`, `blocks=side*side`. Total is `N*(4*N*N-1)/3`. For N=4, counts are 49,25,9,1. After the first layer, height is 25% and cube count 58.33…%. Equal cubes use model units; the percentages do not measure historical time, labour or cost.

`model.js` exposes the same pure API as CommonJS and browser `GizaModel`: `layersFor`, `create`, `advance`, `reset`, `progress`, `cells`, `project`. Cells contain lower-corner coordinates and unique IDs. Completed layers are centred. The state is `{N,built}`; no partially placed layer exists.

## Honest-verdict / design gate

1. **Sentence:** a visible rule builds a model while source labels preserve the boundary with history.
2. **Truth:** the model supplies geometry, counts and progress; the displayed function is that model's actual function. Source reading is distinct from fieldwork or replication.
3. **Subtraction:** no speculative ramp animation, invented workforce, timed historical schedule, ambient movement, network font or decorative effects.
4. **Hierarchy:** the premise, controllable shape and counts, then deeper research evidence. Narrow screens use one column.
5. **Motion:** explicit playback only; each tick adds one whole layer. Reduced-motion preference disables playback while retaining manual steps.
6. **Plain screen:** ivory, ink, cobalt, typography and actual cube edges; no gradients, blur or shadows.
7. **Access:** semantic controls/table/source disclosures, visible focus, targets at least 44px, text equivalents and a non-JavaScript research fallback. Canvas is supplemental; no physical-phone or assistive-technology certification is claimed.

Historical boundary: the regular cubes and lower-layer-first rule are invented simplifications. Merer's transport record does not describe a pyramid lifting method; river proxies do not give a daily delivery schedule; Hatnub is another quarry site. No specific ramp system, workforce count or building duration is inferred.
